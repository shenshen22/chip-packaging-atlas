# 開發紀錄｜Chip Packaging Atlas

這份紀錄用於說明：如何將課堂「建立 AGENTS.md」要求轉化為一個可持續擴充的實際網站。

## 初始需求

- 主題：半導體先進封裝技術圖鑑。
- 學習動機：希望了解先進封裝研發（RD）會遇到的結構、互連與可靠度問題。
- 與一般靜態介紹頁不同：新增內容時應直接沿用同一套資料規格、介面與驗證流程。

## AI 協作與設計決策

| 設計階段 | 討論／問題 | 調整與結果 |
| --- | --- | --- |
| 資訊架構 | CoWoS、TSV、Hybrid Bonding 不屬於同一層級，如何避免誤導？ | 增加三類固定標籤：「封裝平台」「基礎封裝」「關鍵互連／製程」。 |
| 內容管理 | 未來每新增一篇技術，是否都要複製 HTML？ | 將內容集中在 `data/technologies.js`，由共用模板同步生成卡片、詳情頁、比較器。 |
| 互動功能 | 只有技術卡片是否不夠好用？ | 加入搜尋、篩選、雙欄比較、名詞查詢與瀏覽器端收藏。 |
| 可靠度 | AI 會不會自行加入錯誤的精密規格？ | `AGENTS.md` 明訂必須有官方或論文來源、不得杜撰數字、示意圖必須加非比例說明。 |
| 可延伸性 | 如何確認 AI 真的能依照同一套規則繼續新增？ | 設計欄位契約與 `scripts/validate.mjs`，並在 `ADD_NEW_TOPIC.md` 提供擴充示例。 |

## Prompt（AI 協作內容）

> 請協助我建立一個名為 Chip Packaging Atlas 的 GitHub Pages 靜態網站，目標是讓初學者以結構、用途與工程挑戰理解半導體先進封裝。網站需包含圖鑑首頁、技術條目、兩技術比較器、名詞表。請把內容集中於同一份資料來源，並建立具體 AGENTS.md，規範新增技術的欄位、分類、來源查證、命名與測試。請勿編造精密製程數字，技術示意圖要標明非比例。最終專案應可直接上傳 GitHub Pages。

AI 提供了網站結構、程式碼與草稿文字；條目來源放在資料檔中，可逐一點開檢查。上面的 Prompt 是本次協作需求摘要，可作為作業描述；**實際 Prompt／生成結果截圖請直接截取本次真實對話，勿把摘要偽裝成完整聊天紀錄**。

## 驗證紀錄

| 檢查項目 | 方法 | 實際結果 |
| --- | --- | --- |
| 靜態檔案與內容契約 | `node scripts/validate.mjs` | **PASS**：10 項技術、12 個名詞、5 個 HTML 頁面；JavaScript 語法檢查通過 |
| 首頁搜尋與類別篩選 | 輸入 TSV 並切換分類 | **通過**：搜尋 TSV 顯示 1 筆；切至封裝平台顯示 0 筆，符合分類規則 |
| 詳細頁／來源連結 | 從首頁進入 CoWoS | **通過**：詳細頁、示意圖、研究問題及 TSMC 來源連結均顯示 |
| A/B 技術比較 | 選取 SoIC 與 Hybrid Bonding，再按交換 | **通過**：雙側內容與 6 組比較欄位顯示；交換後 A 變成 Hybrid Bonding |
| 名詞表搜尋 | 輸入 RDL | **通過**：顯示與 RDL 相關的名詞內容 |
| 桌機版畫面 | 瀏覽器實際檢查 | **通過**：首頁、詳情頁、比較器主要元件可讀 |
| 手機版 | 瀏覽器模擬 375px | **待人工實測**：已實作響應式 CSS，但尚未完成指定寬度的視覺驗證 |
| GitHub Pages 公開網址 | 無痕視窗確認 | GitHub 發布後填寫 |

## 後續擴充計畫

下一次可新增 3D IC 散熱、Underfill、Interposer 等主題。AI 只需照 `AGENTS.md` 第 5 節新增資料物件並跑驗證，而非重新設計網站。未查證的技術內容不直接發布。
